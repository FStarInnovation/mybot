# LLM Wiki Schema

Этот документ определяет структуру, конвенции и воркфлоу для LLM-управляемой вики проекта MyBot.
LLM (Claude Code) является единственным автором wiki-страниц. Человек курирует источники и задает вопросы.

---

## Структура директорий

```
wiki/
├── SCHEMA.md          # Этот файл — правила и воркфлоу
├── index.md           # Каталог всех страниц по категориям
├── log.md             # Append-only хронологический лог
├── raw/               # Неизменяемые источники (LLM НЕ модифицирует)
│   ├── reports/       # Отчёты и исследования
│   ├── specs/         # Спецификации и API-документация
│   ├── articles/      # Внешние статьи
│   └── assets/        # Изображения и медиа
├── summaries/         # Краткие выжимки из каждого источника
├── entities/          # Конкретные вещи: сервисы, API, библиотеки
├── concepts/          # Архитектурные решения, паттерны, подходы
├── comparisons/       # Сравнительные таблицы
└── overviews/         # Обзорные синтезы по темам
```

## Типы страниц и frontmatter

Каждая wiki-страница **обязана** начинаться с YAML frontmatter.

### Summary (summaries/)
```yaml
---
title: "Название источника"
type: summary
source: raw/reports/filename.md
tags: [tag1, tag2]
created: YYYY-MM-DD
updated: YYYY-MM-DD
---
```
Содержит: ключевые выводы, основные идеи, важные детали из одного источника.

### Entity (entities/)
```yaml
---
title: "Название сущности"
type: entity
tags: [category1, category2]
sources: [raw/specs/file1.md, raw/reports/file2.md]
created: YYYY-MM-DD
updated: YYYY-MM-DD
---
```
Содержит: что это, зачем используется, как интегрировано в проект, ключевые параметры/API.

### Concept (concepts/)
```yaml
---
title: "Название концепции"
type: concept
tags: [architecture, pattern]
sources: [raw/specs/file1.md]
created: YYYY-MM-DD
updated: YYYY-MM-DD
---
```
Содержит: описание паттерна/решения, мотивация, trade-offs, как реализовано в проекте.

### Comparison (comparisons/)
```yaml
---
title: "X vs Y"
type: comparison
tags: [comparison, category]
sources: [raw/file1.md, raw/file2.md]
created: YYYY-MM-DD
updated: YYYY-MM-DD
---
```
Содержит: таблица сравнения, плюсы/минусы, рекомендации.

### Overview (overviews/)
```yaml
---
title: "Обзор темы"
type: overview
tags: [theme]
sources: [список источников]
created: YYYY-MM-DD
updated: YYYY-MM-DD
---
```
Содержит: синтез по теме из нескольких источников, общая картина.

## Конвенции именования файлов

- Kebab-case: `runpod-integration.md`, `memory-tiers.md`
- Без пробелов, без заглавных букв в имени файла
- Имя файла отражает содержание: `entities/qdrant.md`, `concepts/semantic-search.md`

---

## Перекрёстные ссылки

Используй Obsidian-совместимый формат wiki-ссылок:

- На entity: `[[entities/runpod|RunPod]]`
- На concept: `[[concepts/memory-tiers|Memory Tiers]]`
- На summary: `[[summaries/deployment-guide|Deployment Guide Summary]]`

Каждая страница должна содержать секцию **See also** со ссылками на связанные страницы.

## Операции

### Ingest (приём источника)

1. Файл помещается в `raw/` (нужная подпапка)
2. LLM читает источник полностью
3. LLM обсуждает ключевые выводы с пользователем
4. LLM создаёт страницу-summary в `summaries/`
5. LLM создаёт или обновляет entity/concept страницы (обычно 5-15 страниц)
6. LLM обновляет `index.md` — добавляет новые страницы
7. LLM добавляет запись в `log.md`
8. LLM проверяет перекрёстные ссылки на новых/обновлённых страницах

**Правило**: один источник за раз. Batch-ingest возможен, но менее качественен.

### Query (запрос)

1. LLM читает `index.md` для поиска релевантных страниц
2. LLM читает найденные страницы
3. LLM синтезирует ответ с цитатами на wiki-страницы
4. Если ответ ценный — LLM сохраняет его как новую страницу (comparison, overview)
5. LLM записывает query в `log.md`

### Lint (проверка здоровья)

Запускается периодически или по запросу. Проверяет:

- [ ] Противоречия между страницами
- [ ] Устаревшие утверждения (новые источники опровергают старые)
- [ ] Сиротские страницы (нет входящих ссылок)
- [ ] Упомянутые, но не созданные концепции/сущности
- [ ] Отсутствующие перекрёстные ссылки
- [ ] Пробелы в знаниях — что стоит исследовать дополнительно
- [ ] Страницы без `sources` в frontmatter

Результат линта записывается в `log.md`.

---

## Правила для LLM

1. **Никогда не модифицируй файлы в `raw/`** — это неизменяемые источники
2. **Всегда обновляй `index.md`** при создании/удалении страниц
3. **Всегда записывай в `log.md`** при выполнении операций
4. **Всегда добавляй frontmatter** к каждой wiki-странице
5. **Обновляй `updated` дату** при модификации существующей страницы
6. **Добавляй See also** секцию со ссылками на связанные страницы
7. **Используй wiki-ссылки** `[[path|Title]]` для перекрёстных ссылок
8. **Цитируй источники** — каждое утверждение должно быть привязано к raw-источнику
